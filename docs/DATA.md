# Data reference

This document lists every file the pipeline reads or writes, its format, and where it comes from. Paths are relative to `Final_Project_Computer_Vision/`, which must be the working directory when you run the notebooks.

## Summary

| File | Type | Role | Read by | Written by |
|---|---|---|---|---|
| `videos_for_frames/fine_tune_*.mp4` | MP4 video | Source clips for annotation frames | `frame_video.ipynb` (expects them in `more_frames/`) | Downloaded manually |
| `frames/*.jpg` | JPEG images | Frames for Roboflow annotation | Roboflow (manual upload) | `frame_video.ipynb` |
| `weights.pt` | PyTorch / Ultralytics weights | Fine-tuned detector | `main.ipynb` cells 1, 2 | Roboflow (outside repo) |
| `test_2.mp4` | MP4 video | Video to track | `main.ipynb` cells 2, 3 | Downloaded manually |
| `test_3.mp4` | MP4 video | Unused | nothing | Downloaded manually |
| `background.jpeg` | JPEG image | Empty court for movement map | `main.ipynb` cell 3 | Unknown (not generated by code) |
| `tracked_basketball.mp4` | MP4 video | Annotated output | you | `main.ipynb` cell 2 |
| `player_positions.csv` | CSV | Per-frame positions | `main.ipynb` cells 3, 5, 6, 7 | `main.ipynb` cell 2 |
| `Notes.txt` | Plain text | Links and instructor feedback | you | Hand-written |

## Input files

### Source videos (`videos_for_frames/`)

- **Contents:** `fine_tune_1.mp4` through `fine_tune_10.mp4`.
- **What they show:** animated top-down half-court play diagrams with players drawn as orange digits `1`–`5` and a basketball icon (the "Basketball play diagram" playlist in `Notes.txt`). Extracted frames are 720 × 1280 (portrait).
- **How they were obtained:** `Notes.txt` records downloading 720p MP4s with an online YouTube downloader and trimming them with an online video editor. No script in the repository fetches or edits them.
- **Path caveat:** `frame_video.ipynb` reads from `input_folder = "more_frames"`. Change it to `"videos_for_frames"` before running.
- **Duplicates:** `fine_tune_1.mp4` and `fine_tune_8.mp4` are byte-identical (same MD5), so `frames/` contains two identical sets of 10 frames.

### `weights.pt`

- **Format:** Ultralytics YOLO weights file, about 44 MB, loaded with `YOLO("weights.pt")`.
- **Classes:** `{0: 'ball', 1: 'player_1', 2: 'player_2', 3: 'player_3', 4: 'player_4', 5: 'player_5'}` (from the saved output of `main.ipynb` cell 1).
- **Origin:** fine-tuned on Roboflow from the extracted frames. The Roboflow URL in `Notes.txt` contains `yolo26s`, suggesting a YOLO26-small base. The repository contains no training data labels, config, or metrics for this file.

### `test_2.mp4`

- **Role:** the only video `main.ipynb` processes (`video_path = "test_2.mp4"` in cell 2; hard-coded again in cell 3).
- **Properties (from saved outputs and the CSV):** 720 × 1280, 60 fps, 1,120 frames (about 18.7 s).
- It is **not** byte-identical to any `fine_tune_*.mp4`. Whether it shows the same play as a training clip is not recorded.

### `test_3.mp4`

- Not referenced by any code.
- Byte-identical to `videos_for_frames/fine_tune_10.mp4`. If you use it as a test video, you test on a clip whose frames were extracted for training.

### `background.jpeg`

- **Format:** JPEG, 1080 × 1920 (portrait), showing the empty half-court diagram without players, logos, or text.
- **Use:** cell 3 resizes it to the video's width and height with `cv2.INTER_AREA` and draws it behind the movement paths. Because it shares the video's aspect ratio and layout, CSV pixel coordinates line up with the court lines after resizing.
- **Origin:** not generated by any code in the repository.

## Output files

### `frames/*.jpg`

- **Produced by:** `frame_video.ipynb`.
- **Naming:** `<video_base_name>_frame_<NN>.jpg`, where `NN` is a zero-padded index `00`–`09`. Example: `fine_tune_4_frame_06.jpg`.
- **Contents:** 10 **consecutive** frames per video, starting 1 s in. The repository holds 100 files (10 per video), all 720 × 1280.
- **Encoding:** OpenCV `cv2.imwrite` default JPEG quality.

### `tracked_basketball.mp4`

- **Produced by:** `main.ipynb` cell 2.
- **Format:** MP4 container, `mp4v` (MPEG-4 Part 2) codec, same frame rate and resolution as the input. Every input frame is written, including frames with no detections.
- **Overlays:** for each detection that passes the jump filter, a 2 px box (red for `ball`, green for players) and a label like `player_3 ID:3`.
- Some browsers cannot play `mp4v`. Use VLC or re-encode to H.264.

### `player_positions.csv`

- **Produced by:** `main.ipynb` cell 2 with Python's `csv.writer` (comma-separated, `\r\n` line endings, header row, no index column).
- **Granularity:** one row per accepted detection. A frame has up to six rows (one per class). Rows within a frame appear in the order Ultralytics returned the boxes, not sorted by class.
- **Overwritten** every time you run cell 2.

#### Column schema

| Column | Type | Units | Description |
|---|---|---|---|
| `frame` | int | frame index | Zero-based index of the frame in the input video |
| `time_seconds` | float (3 dp) | seconds | `frame / fps`, rounded to 3 decimals |
| `class` | string | — | Detector class name: `ball`, `player_1`, `player_2`, `player_3`, `player_4`, or `player_5` |
| `track_id` | int | — | Fixed ID derived from the class (`ball` = 0, `player_N` = N). **Not** the BoT-SORT tracker ID |
| `x` | float (2 dp) | pixels | Horizontal center of the bounding box; origin at the top-left of the frame, increasing right |
| `y` | float (2 dp) | pixels | Vertical center of the bounding box; origin at the top-left, increasing downward |
| `confidence` | float (3 dp) | 0–1 | Detector confidence; always ≥ 0.25 because of `CONFIDENCE = 0.25` |

Box width and height are **not** saved. Positions are image pixels, not court coordinates in feet or meters.

Missing `ball` rows mean the detector did not return a ball box above `CONFIDENCE`, or the jump filter rejected it. The CSV does not distinguish the two cases.

#### Loading the CSV

The analysis cells load it with pandas:

```python
import pandas as pd

df = pd.read_csv("player_positions.csv")
player = df[df["class"] == "player_1"].sort_values("frame")
```

When you compute movement between rows, compare only consecutive frames (`frame_gap == 1`), as cells 5–7 do, because classes can be missing for some frames.

### Movement map (not saved)

`main.ipynb` cell 3 renders a matplotlib figure titled "Basketball Object Movement Map" and calls `plt.show()`. It does not write an image file. To keep it, add `fig.savefig("movement_map.png")` before `plt.show()` in your own copy, or save it from the Jupyter output.
